# 旧记录读取与新请求校验分离

本阶段已实现并测试 pruned-v2 有限入口的历史读取兼容性。修改配置验证路径，没有更改场景生成、请求提示、预算核心、九个既有源文件 pin、原额度/价格/失效时间或三笔真实 unknown 占用。没有访问用户 Store 或发真实请求。

## 结果与合同

| 操作 | 升级后规则 |
| --- | --- |
| 读取已经保存的 pruned-v2 配置 | 与固定历史合同逐项同形/指纹一致；不以当前源码摘要决定旧数据是否可读 |
| 查看账目/失败结果 | 校验实际 allowance 与配置相符、运行身份和既有旧占用；不重新批准、不清算、不生成 |
| 已完成梦境重放 | 可以无 Key 查看已存梦和视图，即使已经过期或当前源码不再匹配；撤回/删除仍清除正文 |
| proposal / init / 取得生成输入 | 核验当前九个源码 pin、固定虚构 fixture；init 继续需要原精确批准参数、保留旧占用确认和有效期 |
| 预检/准备新请求 | 增加 sourcePinsMatch；不匹配时 ready=false / pruned_v2_protocol_source_changed。原过期、撤回、未知账项及额度门保留 |

`src/pruned-v2-reviewed-profile.js` 保存固定的旧合同模板，并仅返回深拷贝。该模板从重构前项目内已评审 proposal＋allowance 形状捕获，不来自用户配置或账本；其 approved 字段是匹配已有持久化配置的预期数据，**不是初始化账户或发送请求的许可**。没有自动写文件、加载凭据、导入配置指定的模块或动态回调。缺配置仍拒绝；篡改 pin、额度、价格、到期、外发标志或额外字段仍拒绝，返回对象修改不改变内部模板。

历史模板保留原协议身份、fixture 摘要/来源编号版本、九个源码摘要、模式、1 run/3 calls/CNY3、400 输出限制及价格快照和 2026-10-16T12:10Z 到期时间。不改写已批准文件或账户。历史价格只是历史数据，不作为新的报价或授权；不能通过重复 init 延期、重置或扩大限额。

`prunedV2SourcePinsMatch` 读取当前源码（只规范 CRLF）；漂移/读取失败均返回 false。新 proposal 仍拒绝不匹配；init 和生成输入额外明确调用当前实现校验。CLI 已有同 owner lock 下的 state/input 检查在访问环境 Key 前运行，故源码漂移阻断时不会读 Key、创建新 reservation 或 dispatch。已完成的 run --live 分支只是已存结果重放，不是再调用模型。

## 验证与范围

新七项测试使用仓库外临时源副本、公开虚构 fixture、独立合成账项和 dummy 凭据。测试准备已完成/失败场景时，进程内替代 fetch 返回固定 JSON；没有外部 HTTP。随后在复制的 ledger/client/runtime 加无行为注释，复现真实源码摘要漂移，而不改工作树的 pinned 文件。

CLI 子进程通过环境对象代理记录 NIGHTVOYAGE_DEEPSEEK_KEY 属性访问，同时为 native fetch 设置标记。漂移/过期/篡改阻断、历史 read 和已完成重放均无 Key 或 fetch 访问。对照前后 billing.accounts 深相等、配置文件文本不变；新第三笔 unknown 保留完整 2.2032 元，前两笔也不变。所有金额是独立合成机制测试，非用户发票验证。

覆盖未开始、第三笔失败、已完成、撤回、过期、配置/allowance 篡改及不可变模板。已完成后撤回，旧梦/视图变 null；源码变化不绕过正文清除。旧大小审查中的受控 pin 探针已改成回归断言：当前 proposal 仍拒绝，历史配置读取则成功；之前的旧行为证据保留为历史记录，不倒改原日志。

既有相关定向21/21，新测试7/7；最终 Linux LF 全套 **267/267**（零失败/跳过），临时 Linux CRLF 新7＋pruned入口13＋大小8 定向 **28/28**。不是 Windows 原生结果。本轮未出现失败测试；原辅助 fixture 构造来自本项目既有测试，放在 test-support 避免被计作空测试。直接输出和源摘要见 `docs/validation/historical-read-*`。同作者复查，不是独立审计。

本次只分离 pruned-v2 的固定合同读取与当前九个源码 pin；更早入口的既有固定协议/fixture 审查仍保持，不承诺任意旧版本、缺失模块或损坏安装都可读取。将来继续升级时仍要维护旧规范器、来源撤回规则及兼容的账本结构，不能因历史数据可读就接受任意旧源码执行或未知协议。

## 下一步

接下来可按独立版本实施 coupled 的门控预算核心，使用明确匹配的新 allowance，仅以本地 HTTP stub 验证原子保存、未知保留、取消/撤回与中断恢复；新版本不会复用旧额度。当前没有实现该预算协议、付费 CLI 或新真实试跑授权。

原存储/备份边界不变：受管理文件/journal 清正文，外部副本/终端/备份/供应商保存和物理擦除不由本修复自动处理。无第三方实现复制、依赖、私人资料或跨仓库修改。真实生成质量、语义支持和 Asteria 接入仍未验收；Asteria 适配器待对接。
