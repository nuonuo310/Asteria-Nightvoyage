# 有限引文 v2：版本绑定预算核心

本阶段完成代码接线与模拟验证。不是新增真实试跑：没有新 CLI、用户额度初始化、凭据读取或真实请求。旧两笔 unknown 占用保留；没有迁移旧梦、重试旧失败或清算未知费用。

## 协议与额度合同

| 场景 | 身份 / 规则 |
| --- | --- |
| 本地模拟 | `offline-compact-quotes-v2-pruned-unused`；仍要求明确 simulator |
| 预算核心 | `compact-appraisal-quotes-v2-pruned-unused`；显式 selector `compact-appraisal-v2` |
| 新预算核心额度 | 必须不可变地绑定同名 `protocolVersion`；模式、有效期、价格、调用/运行/金额上限仍校验 |
| 旧额度 | 未绑定字段保持原数据形状与指纹；不能重新绑定或用于 v2 |
| 执行与恢复 | 核对 allowance、billing protocol 与 appraisal protocol；不同版本/账户检查点拒绝混用 |

`src/compact-v2-protocol.js` 复用本项目已有校验和归一化模块，建立独立身份。仅在严格校验器到达 unused guard 后移除已校验未引用项并重排索引，再跑完整检查；不修正文案、数值、链接或依据。程序拥有计数审计；无依据值仍为 null/not_stated，模拟情绪单列。清理后的引文逐字匹配不等于语义支持。

保存场景、归一化计数和 settled 账项沿用同一次 Store 原子保存。保存失败不能发布场景；进程在提交后退出，重开可显式续跑剩余阶段而不重付已提交阶段。dispatch 后未结算退出保持 unknown 全额占用，不自动重发。恢复只能校验受管理检查点与计数一致性；未保留原表，不能重建已丢弃引文。

v2 的拒绝原因只在匹配协议绑定账户中保存固定白名单字段，不保存错误自由文本或被拒绝正文。旧 v1 诊断文件及四个既有协议源码 pin 不变。醒来仍是已有场景的连续逐字摘录；新事件拒绝，无第四次修复调用。

## 传输与撤回边界

新 API **具备受门控的 live 分支**，但默认 disabled，必须显式选择协议、启用 live、提供匹配已批准额度、虚构素材外发权限和凭据才可发送；live 禁止 HTTP override。此次只使用独立 stub，没有调用该真实分支。没有现成 v2 付费 CLI 或新付费授权，不能使用旧额度自行开跑。

取消抑制迟到结果；撤回/删除清除受管理梦境、依据、审计、后代和召回，重开不恢复。账本只保留来源编号/版本与无正文计费元数据。没有新增缓存、索引、日志或备份；受管理单文件/临时文件和持久撤回日志边界沿用合同。Store 外已交付副本、用户终端、外部备份、供应商保存和物理擦除不由此自动清除。
