# 梦境质量评估方案 v1

状态：离线素材与评估方案已准备；尚未对这组素材进行真实模型生成。本文是项目自行制定的工程评估方法，不是经验证的心理学量表，不声称证明主观做梦或情感体验。

## 这轮要回答什么

现有小样本已经证明了用户本地的调用、保存、醒来记录、预算封顶，以及一个有依据的醒来摘录样例；它们不足以证明梦境整体质量。接下来需要区分：流程是否正确、内容是否符合约定、作为梦的片段是否自然且有变化。三者分别记录，不能用测试数量或文笔好看来替代其他结论。

原梦可以平淡、温暖、奇怪或令人不安；没有指定情绪比例。没有启示、没有关系主题、没有工作主题、没有明确结局，都可以是合格内容。梦中出现不可能的空间或突然变化也可以成立，不把现实叙事的严密因果当作唯一标准。

## 六组独立编写的虚构输入

文件位于 `fixtures/quality/`，入口为 `manifest.json`。输入虚构身份与输出梦境身份仍分别判断。全部来源默认 `modelEgress:false`，manifest 也明确没有外发和付费评估批准。素材由本项目独立编写，按项目 MIT 许可提供，没有复制私有研究、聊天、私人记忆或第三方样例。

| 素材 | 主要变化条件 | 主要观察 |
| --- | --- | --- |
| courtyard-cloth | 日常院子，低唤醒、略舒展的初始情绪 | 普通素材能否保持自然，不被强加大事件或启示 |
| empty-platform | 空站台与一个未完成的小意图 | 意图能否留下影响而不被强行解决，不变成现实任务 |
| drawer-and-orbit | 抽屉与天象馆的两个不相关片段 | 是否存在可感受的组合变化，而非只能逐条复述 |
| weather-room | 雾中小屋，较警觉、不安的初始情绪 | 情绪是否有事件依据，不机械升级恐惧或安排安慰 |
| two-maps | 两张不同的地图与未解决的当前关切 | 能否保留不确定，不凭空断言哪个解释为真 |
| sparse-context | 背景不可用、Mind 拒绝、意图过期 | 缺失输入是否保持明确，梦中想象是否仍带梦境身份 |

这些不是预定剧情，也不要求把每条素材都写入梦。叙述可以创造虚构角色；不得把创作出的角色背景反填为已获准的输入，更不能写成真实用户的经历、人格或责任。当前无性别叙述要求作为一项可记录的风格约定，偏离它不等同于发现现实身份。

## 两次阅读，分开记录

第一次只看原梦分幕，记录片段是否可感、变化是否有承接、哪些地方显得套话或僵硬。不要先看情绪数值再反推“应该感到什么”。普通、未解决或空洞的结尾不自动扣分；空洞指缺少可感受的内容，不是缺少人生道理。

第二次对照获准输入、原梦、模拟情绪、醒来记录和来源字段，逐项核对。记录具体依据和不确定项，不为通过评估而替模型补出未写出的情节。对摘录规则的符合不能代替对摘录是否有用、是否断章取义的判断。

| 维度 | 要观察的具体问题 | 判断性质 |
| --- | --- | --- |
| 来源与权限 | 输入身份、输出 origin、非事实标记和来源引用是否齐全；是否越权使用缺失通道 | 程序检查与人工内容检查分开 |
| 原梦与后续分离 | 原幕是否未被醒来记录、回想或续写覆盖；新情节是否误写成回忆 | 身份与内容分别检查 |
| 分幕变化 | 第二幕有承接或可辨认的梦式转变吗；是否只是重复第一幕 | 人工判断，不要求现实主义因果 |
| 情绪演变 | 数值范围和前后衔接是否正确；事件是否支持这一变化 | 数值是机制证据，支持关系是人工判断 |
| 醒来摘录 | fragment 是否逐字来自所指原幕；选取是否有意义、有没有遗漏关键否定语境 | 精确匹配与语义质量分开 |
| 余韵与可访问程度 | 模拟余韵是否独立于梦中情绪；珍藏、日常召回是否被混成同一开关 | 机制检查，不能由文笔推断 |
| 联想与接受边界 | 可以为空；出现时是否保持待验证、非事实，不直接改记忆、人格或任务 | 人工检查与权限检查 |
| 表达与重复 | 视角是否符合当前约定；是否反复套用固定物件、情绪曲线或收尾句 | 人工判断，有限样本不能推出频率规律 |

每项用 `pass / concern / fail / not_assessed`，附短理由和本地证据位置。不能把 `not_assessed` 当成通过，不做一个加权总分来抵消来源越界。程序能证明的只写程序结论；人工读出的好坏和不确定性单独写。

## 最小验收与停止条件

- 来源丢失、梦境被表述成现实指控、缺失通道被冒充为已获准输入、原梦被覆盖或执行了现实动作：该样例失败，停止扩大实验范围，先查原因。
- 摘录不符合协议：由现有校验拒绝发布，保留调用与预算占用；记录为拒绝/失败样例，不悄悄换成另一场，不自动增加修复调用。
- 内容普通、没有联想、没有启示、未解决意图：允许，不是停止条件。
- 叙述视角、情绪依据或摘录意义存在问题：保留为质量 concern/fail，不把主观问题伪装成“测试全绿已解决”。可提出下一轮改动，但不要在同一对照批次中途悄悄改提示词。

单个合格样例只支持该样例的限定结论。六组素材也不能保证覆盖全部情绪、长期生活或未来真实记忆；本阶段不引入真实私人材料。

## 记录与对照

`docs/templates/quality-review.json` 是未填写的结构模板；实际填写副本、原梦和完整回执放到源码仓库外。公开仓库只提交经过检查的汇总、方法和虚构输入，不自动上传实际运行梦簿或截图。

一个评估批次固定模型、协议、提示词源码版本、素材版本、幕数和输出上限，记录实际失败与预算占用。先登记所有预定样例，再生成，避免只挑好看的几场。可以做不同版本的人工对照阅读，但不新增自动模型评分调用，不建立噩梦/美梦配额。

建议下一次最小筛查从 courtyard-cloth、drawer-and-orbit、sparse-context 各一场开始，最多九次调用。这只是待批准方案，不是新的外发或费用授权。看完覆盖缺口后再决定是否扩到六组或增加重复；改动后的模型、价格、输入外发范围和总额度必须先核对并明确批准。已有两轮额度保持完成状态，不重置。

## 已完成的离线检查

在仓库运行：

```sh
node scripts/check-quality-pack.mjs
```

该脚本只读取这组源码内虚构输入，使用 `Nightvoyage` 的确定性假模型，在系统临时目录创建并清理测试数据。它不读取密钥、不调用 HTTP、不改动用户梦簿，也不启用真实提供商。默认真实入口仍只接受此前固定的单一素材；本方案没有偷偷把新素材接入付费入口。

本轮 Linux 检查：六组输入合同通过、本地文件适配器与直接输入一致、六次假模型闭环可重开读取，共十八次**假模型阶段调用**，真实模型请求为零。直接输出与源码/素材哈希位于 `docs/validation/quality-pack-offline.*`。这些检查没有评估叙事质量；假模型对不同素材的响应不用于质量排名。未新增运行时依赖或第三方代码。没有重跑现有 90 项机制套件，也不把旧套件结果绑定到新增的素材质量上。
