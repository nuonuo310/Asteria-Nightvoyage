# Fixed local final-answer completion

## Purpose and current scope

The Windows selected-refusal receipt qualifies one fixed unsupported interaction call. It does not exercise an ordinary final answer or complete a dream. This separate local mode exercises that next transport boundary: one fixed fictional response, a bound agent message, and a successful turn completion. No account, model inference, API key or user book is used. The default command starts an independent Node peer, not Codex.

The explicit native entry uses the existing fresh owned state/profile/cwd and checked fictional catalogue, no inherited credential environment, one ephemeral thread and empty turn environments. It serves one independently written SSE final message from its owned loopback provider only after the actual request declares an empty tools array. The served text is fixed fictional test data; generatedResponseSupplied means this scripted fixture was supplied, never real model output. A second POST is refused. There is one turn, no repair, fallback, caller response override or live flag.

The new mode has no expected-error continuation exception. Startup errors still block. It requests only the existing exact account-rate notification opt-out, with enforcement unverified; an incoming unreviewed notification is still rejected. The previous refusal and observer entry points retain their behavior.

## Completion checks

A separately bounded reviewer requires the prepared thread/turn IDs, one final-answer agent item start, matching item completion and the exact fixed text. Deltas are bounded and discarded. It requires turn status completed without an error; failed/interrupted turns, different identities, changed text, duplicates, hidden non-message items, tool/approval requests, missing completion, timeout and cancellation cannot yield a successful result. Token-usage notifications are bounded by the same transport limits and checked for the current thread and object shape; their payload is discarded and usage remains unknown. No token totals or entitlement follow from them.

The result contains metadata only: fixedAnswerMatched, itemIdentityChecked and turnCompleted. It returns no response text, partial output, raw account data, provider IDs or tool arguments. The fixed local text is not passed into the dream engine, validated as a dream stage or written into a book. Closing the owned process and removing its temporary workspace are still required. Descendant termination and background network containment remain unverified.

Commands:

- `node --test test/codex-final-completion.test.js`
- `node scripts/check-codex-final-completion.mjs` — independent peer only.
- `node scripts/check-codex-final-completion.mjs --native-executable ABSOLUTE_NATIVE_CODEX_PATH` — explicit installed native comparison, no account or real provider.
