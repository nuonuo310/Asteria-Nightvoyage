# Separate one-request event-location diagnostic

## State and boundary

Implemented and synthetically tested; awaiting a new real-request approval. This is a diagnostic, not a full dream trial or a continuation of any old run. Native contract `plan-event-witness-probe-v1`, transport `plan-event-witness-probe-http-v1`, and metadata policy [closed-response-event-witness-v1](CLOSED-RESPONSE-EVENT-WITNESS.md) have separate identities. Existing consumed diagnostics remain terminal and unchanged.

The fixed model remains GPT-5.6-Sol and input is the pinned independent fictional window snapshot. At most one new first-scene request intent is allowed. It cannot request a second scene/wake, publish a dream, repair output, retry, switch provider/model or call a fee-based API. Fake remains the test default; DeepSeek/API legacy behavior and formal Asteria ownership are unchanged. Native Codex and Asteria bridges remain pending.

## Durable owner

Eight predecessor paths are mandatory and absolute at the library boundary. The latest predecessor must be the exact consumed one-request `unreviewed_event` result: rejected, one intent, unknown usage, no body/dream publication, completed authorization action and revocation confirmed. Its closed receipt and source closure are hash-bound. All other historical checks and source withdrawals remain enforced; a different failed diagnostic is not interchangeable.

A new nine-field approval binds the full source closure, static catalog, model, fixture and policy for 24 hours. `approveClosedEventWitness` explicitly adds the metadata described in the policy: a reviewed code plus bounded ordinal, previous reviewed code and namespace/shape/byte band. It does not approve raw outside-catalog names, provider messages, body/key retention or broader generation. Reinitialization never refreshes expiry or clears consumed state. Foreign stores/records cannot be adopted.

Public discovery precheck occurs before authorization; a failed precheck does not log in, dispatch or automatically retry. Authorization intent is saved before browser work; failure there is terminal even with zero generation intents. A request intent is saved before HTTP. Interrupted authorization/dispatch reopens uncertain and cannot authenticate/send again. A completed accepted/rejected outcome replays locally without login or HTTP. Closed auth/network failure metadata persists, while revocation failure remains visible for account cleanup.

Queued cancellation is terminal without dispatch. In-flight cancellation/withdrawal suppresses late output and any witness publication. Active source/owner/account/request/expiry checks continue while reading and are rechecked after a parser/transport failure before any diagnostic is retained. Cancellation or withdrawal during rejected-stream cleanup suppresses the late witness too. Storage failures fail closed; an interrupted final write preserves the previous durable unknown attempt, never a fabricated accepted result or witness. Old accounts, holds, approvals and requests are not reset or settled by this entry.

## Caps and outcomes

The existing fixed HTTP guard remains: 65,536 request/stream bytes, 1,024 structured frames, 1,200 final JSON bytes and a 60-second local HTTP deadline. There is no server output-token cap. Local bounds do not prove remote usage stopped. Money and remote cancellation remain unknown; rejected/incomplete output usage remains unknown. Extra-credit settings are a user assertion only, not remotely verified or a free-inference promise.

- `rejected` with a reviewed event code: stop and review that specific static event schema. A named event is not evidence that a tool executed or quota ran out.
- `rejected` outside the catalog: `provider_contract_unverified_stop`. Do not collect arbitrary names, ignore the event or start another guessed trial. This can establish a compatibility boundary, not its exact raw cause.
- `accepted`: one complete stage passed protocol/shape validation; normalized usage may be recorded. Its body is discarded, no dream/wake is saved, and this is not full-dream qualification or quality acceptance.
- Other failures remain terminal and sanitized. Unknown values are not replaced with zero/free/success claims.
