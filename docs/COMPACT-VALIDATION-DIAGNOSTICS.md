# 共享引文首轮失败与无正文诊断

2026-10-15。用户报告 Windows / Node.js v24.19.0 下 148 项测试通过，本地共享引文模拟为三次结算、成功重开、重复调用零次、真实请求零次。随后明确批准固定 sparse-context 虚构素材外发及新增人民币 3 元、一场/三次调用上限；提供商官网价格与已有保守价格配置核对一致，未延长到期时间。

用户随后报告真实入口第一幕失败：`compact_appraisal_invalid`、保存幕数零、未发布 dream/wake/appraisalView；只有一次尝试，账本状态 unknown，保留 2,203,200 micro-CNY，预检停止于 `unsettled_attempt_requires_review`。此前账本保持不变。累计为 22 次调用尝试、八次运行、2,240,140 micro-CNY 的已结算或保留金额。**这些是用户提供的本地程序账本信息，不是独立核验的服务商账单；保留额不等于实际费用。** 输入/输出计数零表示没有提交用量结算，不能推断没有 token 消耗。

源码路径显示该错误位于 HTTP/JSON/用量格式检查之后、场景评价规范化阶段。原规范化器已分别拒绝无效表/引用、未使用引文、事件/数字越界、缺失目标或情绪依据等问题，外层统一错误码丢失了分类。原返回正文及细分原因没有保存，不能恢复或断言哪条规则导致这次失败；新增诊断不追溯填入旧记录，也不为取证重复请求。

## 本次实现

新增固定白名单 `validationDiagnostic`，随失败尝试的 unknown 状态在同一个 Store 保存中写入：

```json
{"schemaVersion":1,"protocolVersion":"compact-appraisal-quotes-v1","stage":"scene","check":"invalid_compact_reference"}
```

上例是独立虚构的错误分类示例，**不是本次真实失败原因**。`invalid_compact_reference` 仍可包括索引类型、范围或目标二元组形状问题，不提供模型文本或确切字段路径。其他分类见 `src/validation-diagnostic.js`；非白名单异常只标为 `unclassified_validation_failure`。

客户端直接调用同一个原场景规范化器以保留固定错误分类；对外运行错误仍为 `compact_appraisal_invalid`。账本重建白名单对象，去掉任何额外正文、异常详情、堆栈和用量字段。已有 receipt.billing 会返回该元数据，不增加输出正文、日志、缓存、索引或备份。来源撤回后仍可保留这类固定审计分类，关联正文仍清除。外部复制/备份边界沿用现有合同。

三个已批准协议源码和固定素材摘要均不变。未修改模型提示词、生成合同、输出限额、价格、权限、失败恢复门或未知费用保留策略。有效响应的用量仍只有在原校验/原子结算完成后才提交；本轮没有新增“失败也结算”的路径，不释放既有保留额。
