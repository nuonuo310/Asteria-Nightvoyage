## Frozen implementation constraints

1. **Authorization ownership.** A separate future entry durably records explicit consent, selected fixture/model/protocol and a finite request allowance before obtaining a live handle. No credential string is a public factory option. No existing Codex auth file is read. Model availability alone never enables dispatch. Missing/expired approval or session stops before child launch/token access.
2. **Credential handoff.** The checked session owner alone supplies the access token to a fresh child's ACCESS_TOKEN. The parent process environment is not mutated. Refresh token, ID token, subject and callback are not passed to the child. Never put secrets in argv, config files, receipts, exception strings or console output. Raw child output is untrusted and cannot be echoed. JavaScript reference disposal is not verified memory zeroization; a child receiving a token is inside the trusted boundary, not isolated from it.
3. **App identity.** Use the registered agent_name_hint as the stable initialize name, with explicit human title and application version. Add an independent synthetic assertion for registration/native attribution before real login is proposed. Do not modify the old owner merely to make its evidence appear authenticated.
4. **Native launch.** Explicit reviewed executable and version; owned fresh directories outside checkout; shell=false, finite startup/turn/output bounds, restricted inherited environment, explicit Responses provider and zero request/stream retries. Keep old native fixture factory unchanged. A fresh stage process receives only that immutable authorized stage and completed predecessors; provider thread IDs are transient, never canonical memory.
5. **Tools and containment.** Review actual model metadata and effective tool configuration independently of the fictional catalogue. Existing empty-environment/config observations do not establish all-handler denial. A credential-free local comparison with independent representative metadata must precede any real diagnostic. Account credentials do not belong in that comparison. The first real diagnostic, if later authorized, must remain separate from dream publication until its admission criteria are established. Do not introduce a private endpoint, TLS interception, token relay or custom production catalogue under this contract.
6. **Accounting and pinning.** Persist the external attempt intent before turn/start can cause inference; a later error does not reset the count. Auth discovery/catalogue requests are reported separately from inference intent. Actual provider retries must remain zero. If dispatch occurrence cannot be proved after a crash, preserve ambiguity and block repeat. Run adapter/model/protocol remain fixed; fallback is possible only under explicit zero-call preflight policy. No resume into another adapter.
7. **Response and cancellation.** Bind thread, turn and final item; accept only completed turns, then apply the existing typed stage validator. No fixed fixture answer comparison in real transport, no tool execution, no partial publication, no repair request. Cancel/withdrawal aborts local processing, closes the owned process and suppresses late body. Local closure is not proof of remote cancellation or descendant termination. Keep those receipt fields unknown until measured.
8. **Close and revoke.** Await child exit and report owned-directory cleanup before publishing a stage. The session action must await every child and transport close before returning to OAuth finally. Report cleanup and revocation separately; failed revocation keeps an explicit cleanup notice. No automatic token renewal/restart, background login or continued inference. No claim that revocation cancels an already started remote request.
9. **Persistence.** Store only typed fictional dream/wake outputs and closed metadata. No OAuth values, callback, raw stderr, model reasoning, arbitrary diagnostic text or user-specific paths. Source withdrawal continues to purge bodies and descendant views across restart. Asteria owns canonical memory/Mind/personality/affect/intents; its bridges remain pending.

## Implemented independent credential-owner rehearsal

Run `node scripts/check-codex-plan-credential-owner.mjs`. No arguments are accepted. The script exercises seven closed scenarios: success, timeout, cancellation, a delayed reply after cancellation, failed spawn, failed child and credential-like untrusted output. Every credential is the fixed independently scripted sentinel; no real credential, account, auth directory, network or native executable is supplied. The public rehearsal function accepts only a closed scenario and a bounded timeout. An arbitrary token, executable, endpoint, environment, session or getter cannot be injected.

The independent Node child checks the sentinel in its explicit environment, an environment-key allowlist, absence of the sentinel in argv, and the exact application name Asteria-Nightvoyage. The parent derives that name from the existing registration helper using an independent synthetic transaction without opening its authorization URL. The parent never reads or assigns its ACCESS_TOKEN. It waits for the owned child close before disposing its sentinel reference and simulating revocation; the public result returns only fixed metadata and ordering labels. Failed child stderr is not decoded or emitted; unexpected stdout is rejected, not echoed. Failed-spawn closure means no active owned child, not that a process successfully started.

These checks exercise actual local process/environment/stdio behavior, not a mocked spawn callback. They do not prove native Codex token handling, OS credential confidentiality, descendant termination, remote cancellation/revocation, production redaction, model eligibility or an authenticated transport. The token is a public fixture constant, and dropping a reference is not memory zeroization. The delay scenario proves suppression by local process termination; no real server's late response is involved. No raw output, token, callback URL or temporary private path is returned.

Evidence and exact source hashes: [credential-owner validation](validation/codex-plan-credential-owner.json). The next slice is the credential-free native metadata/tool comparison in the ordered table. It must remain separate from the fictional catalogue's successful empty-tool result.
