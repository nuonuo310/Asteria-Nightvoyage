## Implemented, awaiting fresh real permission

This is a separate native HTTP diagnostic owner, not a repaired dream or a successful subscription inference claim. Its private local metadata is `planEventClassProbe`; its contract is `plan-rejected-event-probe-v1`, with transport protocol `plan-rejected-event-probe-http-v1`. It preserves the consumed aggregate-envelope failure and every preceding approval. It cannot recover the discarded event from that historical request.

The default model-port/Fake behavior, every earlier live parser, source manifest, grant and runtime are unchanged. The new branded HTTP wrapper uses the existing official Responses transport and the previously tested closed [rejected-type classifier](REJECTED-RESPONSE-EVENTS.md). No third-party implementation is copied; this is independent MIT project code. No Asteria bridge or Codex native integration is added.

## Fixed scope

- GPT-5.6-Sol through Sign in with ChatGPT, fixed independent fictional window fixture. The source file retains `modelEgress: false`; only an exact separately approved immutable request grants this fixture egress.
- At most one first-scene request intent. No second scene, wake, publishing, repair, retry, model/provider switch, API key or additional credit permission.
- Stream/request limit 65,536 bytes, aggregate event limit 1,024, final answer limit 1,200 bytes, local HTTP deadline 60 seconds. There is no server output token cap; local limits do not establish remote usage or cancellation.
- A formerly unsupported event still rejects. Only one of seven fixed type categories is retained. No arbitrary event name, event payload, error message/code, reasoning, source text, answer text, callback or credential is recorded.
- A complete supported stream must also pass the unchanged stage validator. `accepted` means that one diagnostic scene passed protocol/shape checks; the generated body is discarded and no dream is saved. It does not qualify narrative quality or account entitlement for a complete dream.
- Rejected/ambiguous requests keep usage unknown. Money and remote cancellation remain unknown. A failed/error event category alone does not diagnose quota exhaustion.

## Approval and state

The predecessor is required to be an exact terminal aggregate trial: failed, one intent, no saved scene/wake, `responses_envelope / unknown_event`, unknown usage, revocation confirmed. Its closed receipt is hash-bound. A changed or withdrawn ancestor blocks this owner. Paths are fixed by the CLI; the library contract requires all seven absolute predecessor paths and rejects extra fields.

A new immutable approval lasts 24 hours and binds the complete current source closure, predecessor manifests, model, protocol, fixture and eight explicit assertions. Reinitialization never refreshes or clears a consumed/expired grant. Old stores and foreign execution metadata cannot be adopted. Missing approval preflight creates no directory and reads no credential.

Public discovery precheck occurs before login. A precheck failure leaves the unconsumed approval unchanged; it does not cause an automatic retry. Once authorization starts, its intent is persisted before browser work. Failed login is terminal even if generation stayed at zero. Authentication failure stage and closed HTTP/network diagnostics persist for replay. The request intent is persisted before invoking HTTP. Interrupted authorization or dispatch reopens as `uncertain`; it cannot authenticate or send again. A completed accepted/rejected result replays locally without login or HTTP.

Queued cancellation consumes zero generation intents and is terminal. In-flight cancellation or source withdrawal suppresses a late answer. Current owner, predecessor identity, account binding, request fingerprint, expiry and source withdrawal are checked before dispatch and while reading. Storage failure prevents a success receipt; interrupted settlement preserves the previous durable uncertain intent. Revocation is attempted by the existing transient-session owner and the result is retained; unconfirmed revocation remains visible for manual account cleanup.
