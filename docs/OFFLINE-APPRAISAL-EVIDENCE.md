# 离线候选：梦中事件评价的可核对依据

状态：`offline-appraisal-evidence-v1` 已实现离线协议、模拟提供者和同一文件梦簿上的候选引擎；没有真实模型结果或费用。它不改变已完成的 v2 付费入口、提示词摘要、输入批准或账本，也不接 Asteria。调用前后的数字相接，与模型评价有道理，是两个问题。

## 候选合同

原有 `event / appraisal / delta` 保留。新增模型输出 `basis`，内容只有短摘录，不索取模型隐藏推理或长段解释：

| 字段 | 无依据时 | 有依据时 | 程序能核对什么 |
| --- | --- | --- | --- |
| `goal` | `goalEffect:0`，依据为 `null` | 非零影响附 `goalExcerpt / outcomeExcerpt` | 两条原幕摘录存在；无法独立理解是否真是目标与结果 |
| `controlExcerpt` | `null`，数字用 `0.5` 兼容占位 | 当前事件的短摘录 | 字面匹配；无法证明控制感强度 |
| `uncertaintyExcerpt` | `null`，数字用 `0.5` 兼容占位 | 当前事件的短摘录 | 字面匹配；无法证明不确定程度 |
| `affectExcerpt` | `null`，两个 delta 都为零 | 当前事件的短摘录 | 字面匹配；无法证明变化方向或幅度合理 |

每条摘录最多 160 个字符，必须非空且逐字连续出现在**本幕事件**。不接受只存在于输入、上幕、事后解释里的文字；不偷偷 trim 或拼接。零目标影响不禁止情绪变化；有惊讶或身体感受，不等于发生了目标得失。

`control / uncertainty` 的 `0.5 + null` **表示未说明、使用占位**，不能对外宣称测出了中等控制感或不确定性。使用者必须同时读取 basis；这也是该候选暂不进入付费核心的原因之一。以后若改为可空数值，需另行评审合同，不能静默换掉现有数据含义。

程序将校验后的摘录写入每幕 `appraisalBasis.evidence`，同时自行标记 `origin:dream_appraisal / isRealityFact:false / verification:literal_excerpt_only / semanticSupport:not_assessed` 及候选协议版本。提供者不能自行声称语义已验证。该对象属于其原幕，来源身份继承梦记录；不能把它脱离父记录转存成现实依据。

提示词要求非零目标影响在梦中正文写出目标及帮助/阻碍结果，但程序仅能检查引用存在。测试刻意放入了“不相关但逐字存在”的引文：它仍满足结构，因此永远保留 `semanticSupport:not_assessed`。**这不是自动心理解释器或语义验真器。** 人工仍须判读引用是否支持该评价；有凭据不等于结论正确。

## 原梦、醒来与保存

`AppraisalRehearsal` 是 `Nightvoyage` 的离线子类，只覆写分幕/醒来规范化并保存候选元数据；使用同一个规范化 snapshot、本地文件 Store、预算/取消/恢复和来源撤回规则。没有另造记忆或人格系统。现有 `FileSnapshotAdapter` 的输出可原样传入。Asteria 适配器仍待对接。

证据附在原幕中持久保存；回想和想象续写不能改原幕。来源撤回和原梦删除沿用现有墓碑，清除原幕及其引文、派生正文；重开先清除再读取。没有新增正文缓存、索引、日志或自动备份。外部复制、旧备份、其他机器和物理擦除仍不在首版自动清除范围。

候选拥有独立 provider/run 协议身份，拒绝直接执行或续跑旧 fake/v2 运行。旧梦可按原接口读取，不迁移、不补写证据、不倒称已通过候选规则。已保存的候选检查点可通过显式恢复继续，不重生成已保存的幕；不自动重试。累计最多两幕加一次醒来，单次输出上限仍为 400。新增证据占用同一输出空间，不额外加解释/评分调用。

候选请求复用本项目 v2 的输入白名单和响应解析，仅在候选模块构建新提示；请求对象没有 HTTP endpoint 或凭据。`OfflineAppraisalProvider` 必须显式提供本地模拟回调，模块没有 fetch、环境密钥读取或真实传输。调用方自定义回调是普通 JavaScript，不能把这说成对任意不可信回调的网络沙箱；本项目测试只使用内存模拟器。

## 另外两项质量关注

- 叙述提示明确用“梦里的人”或省略主语，避免通过换称呼引入性别。暂不做汉字黑名单，以免把正常词语或引用误判成性别事实。这是提示约束，尚未证明真实模型会稳定遵循。
- 醒来仍只允许原幕逐字连续摘录；候选提示要求兼顾辨识度、核心体验和否定语境。程序没有自动评判哪个片段最重要，不把摘录准确等同于选得好。
- 不规定正向收尾、关系/工作主题、启示或美梦/噩梦配额。新增证据规则可能使叙述过于解释化、变短，或让模型倾向零变化，需要真实质量复测前后人工观察。

## 不花钱的本地检查

```powershell
npm.cmd test
node scripts/check-appraisal-rehearsal.mjs
```

`fixtures/appraisal-probes.json` 是独立编写的**预先脚本化虚构输出**，不是模型生成样本或用户梦簿；按项目 MIT 许可发布。演练覆盖普通无变化、明确的目标得失、没有目标得失的情绪变化，在系统临时目录运行后清理。源素材仍全部禁止模型外发。输出只报告机制，不打印梦境正文。

离线测试必须继续覆盖：错误/过长引用、缺证据的数值、无关引用的语义局限、输入降级、程序身份不可伪造、持久化/重开/去重、取消和迟到结果、进程退出后续跑、撤回/删除清除新增正文、旧协议隔离、醒来原规则与不增加修复调用。它们不能证明真实生成质量，也不能代替 Windows 原生执行。正式结果及源码摘要见 `docs/validation/appraisal-rehearsal.*`。

下一步先在本地确认兼容性，人工评审占位语义和证据字段是否值得进入未来真实协议；本轮不改造付费入口、不延长价格有效期，不新增额度。真实复测仍需另行固定协议/输入、核对提供商和批准费用。
